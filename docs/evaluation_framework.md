# LOCKED-CROSS: a coverage-aware cross-screen evaluation framework

Version: 1.0, 2026-10-06.

## Purpose

LOCKED-CROSS is a reproducible evaluation procedure for drug-response models whose claimed use includes transfer between experimental screens. It separates interpolation within a known response graph from transfer to labels generated by another laboratory or assay. The procedure evaluates prediction quality jointly with entity coverage and numerical validity.

The framework is an evaluation method, not a predictive architecture. A model passes or fails under the same contract regardless of whether it is linear, neighborhood-based, matrix-factorization, tree-based, graph-based, or neural.

## Required inputs

1. A development response table with stable `study`, `cell_id`, `drug_id`, and oriented numeric response.
2. Cell and drug features whose preprocessing can be fitted using training entities only.
3. At least one target screen withheld from model family selection, hyperparameter tuning, stopping, endpoint selection, and threshold selection.
4. A file-level manifest recording source URLs, versions, sizes, hashes, licenses, and acquisition dates.
5. A machine-readable model lock containing the selected configuration, protocol hash, development-result hash, seeds, endpoints, and a declaration that target labels were unseen.

## Estimands

Every screen is evaluated in three nonpooled target domains:

- **Full feature-complete domain:** all target pairs for which required features exist.
- **Shared-entity domain:** target pairs whose cell and drug identities both occur in the source, whether or not the exact edge occurs there.
- **Exact-pair domain:** target pairs whose exact cell-drug edge occurs in the source.

The primary ranking estimand is equal-drug-weighted macro Spearman correlation across cells. A drug is eligible only when it has at least five distinct cells and nonconstant observations and predictions. Every estimate is accompanied by the number and fraction of eligible drugs. Pair-weighted metrics are secondary because dense compounds would otherwise dominate.

Absolute-scale outcomes include MAE, RMSE, calibration slope/intercept, prediction range, and the fraction outside the response support. They are interpreted only when the response scale is scientifically comparable. Catastrophic values remain reported even when rank correlation is the primary endpoint.

## Procedure

### 1. Audit identifiers independently of outcomes

Resolve cells and drugs to stable biological identifiers before reading target response values. Exclude ambiguous many-to-one mappings rather than resolving them using performance. Record every exclusion and affected response count.

### 2. Define response orientation and time point

Choose the sign, quality threshold, time point, duplicate rule, and finite-value policy using development metadata. Apply the frozen rule unchanged to target screens. Report retained and excluded rows at each step.

### 3. Fit preprocessing inside each training partition

Imputation, scaling, feature filtering, PCA, feature selection, and representation learning use training entities only. Target features may be transformed by a source-fitted transform but may not influence its parameters. Target outcomes are unavailable to all preprocessing.

### 4. Evaluate source-only interpolation and cold starts

Use random-pair, cold-cell, cold-drug, and cold-both folds. In cold-drug analysis, add a scaffold-grouped split when valid structures are available. Model selection requires defined primary metrics in all three cold-start regimes. The selection score is their unweighted mean; ties are resolved by lower MAE, fewer trainable parameters, and lexical configuration identifier.

Random seeds quantify algorithmic and split stability. They are not independent biological replicates and are not used as the unit of scientific inference.

### 5. Freeze before target-label access

Record the model family, hyperparameters, seeds, preprocessing, target domains, primary and secondary outcomes, exclusions, multiplicity families, and decision thresholds. Hash the protocol and development summaries. Do not update this lock after target labels are read; additions are labelled post-lock sensitivity analyses.

### 6. Evaluate untouched screens without retuning

Fit deterministic models once and stochastic models over the locked seeds. For a stochastic model, compute each drug's metric within each seed and then average across seeds. Do not duplicate deterministic results to create artificial seed replication.

### 7. Match the internal comparator to each target domain

Restrict source random-pair out-of-fold predictions to the target screen's shared entities or exact pairs. Pair internal and external metrics by drug. Define optimism as internal minus external macro Spearman. This separates label-system disagreement from changes in entity composition.

### 8. Quantify uncertainty at biological units

Use a drug-cluster bootstrap for the primary interval and paired model contrasts. Use a crossed cell-and-drug bootstrap as a dependence sensitivity for shared-entity conclusions. Keep seed variability separate. Correct prespecified comparison families for multiplicity.

### 9. Report coverage and failures jointly with accuracy

For each model and domain, report eligible drugs, coverage fraction, macro and median drug-level performance, absolute errors, prediction range, and out-of-support fraction. A model evaluated on fewer drugs cannot be declared the domain winner from its conditional score alone.

### 10. Diagnose feature-domain extrapolation

Fit drug-distance diagnostics using source features only. At minimum report nearest-source similarity or distance and source-standardized feature radius. Evaluate performance and numerical validity by frozen distance quantiles. Any clipping or bounding rule must be defined from the response support or source data before target outcomes are examined; report unclipped and guarded results together.

## Minimum decision rules

- A random-pair optimism claim requires a confidence interval for the target-matched internal-minus-external effect and a prespecified materiality threshold.
- A model-superiority claim requires a paired drug-level effect on the primary untouched screen after multiplicity correction.
- A deployment claim requires adequate coverage, valid absolute scale, and no unresolved catastrophic extrapolation, not merely positive rank correlation.
- Biological interpretation requires evidence independent of the response edges and features used to construct the predictor. Exact computational attribution is not itself biological validation.

## Machine-checkable outputs

The reference implementation produces:

- file manifests and identifier audits;
- split and preprocessing audits;
- a model-lock JSON with verified hashes;
- per-seed, per-fold, per-domain, and per-drug metric tables;
- coverage and out-of-support diagnostics;
- primary drug-cluster and crossed-bootstrap intervals;
- a protocol-deviation table;
- vector figures with machine-readable source CSV files;
- acceptance scripts that verify seeds, keys, hashes, finite values, domain coverage, and manuscript-result consistency.

## Scope

The complete protocol can support a claim about transfer only between the evaluated in-vitro screens and response definitions when the prespecified decision criteria are satisfied. It does not establish patient benefit, clinical calibration, causal drug mechanism, or transfer to laboratories and compound spaces absent from the evaluation.

## Web interface versus complete protocol

`webapp/` implements a reporting layer with two isolated uses: exploring precomputed aggregate study results and analyzing user-supplied observation/prediction tables. The upload interface reports per-drug rank performance, eligible-drug and pair coverage, abstentions, numerical failures, conditional bootstrap intervals, and optional scale diagnostics.

An uploaded prediction table does not reveal whether source preprocessing was leakage-free, identifiers were independently resolved, the model was locked prospectively, or the target labels were untouched. The web report therefore does not certify LOCKED-CROSS compliance or cross-screen utility. User-selected thresholds flag evidence requiring investigation; they are not validated treatment or deployment rules.

Public hosting and the next calibration/abstention experiment are separate steps, defined in `platform_next_study.md`. The website must not be described as a validated clinical or drug-recommendation platform.
